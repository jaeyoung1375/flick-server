# 프로젝트 정체성 (flick-server Overview)

이 문서는 AI 작업용 사실 정리입니다. 프로젝트의 주관적 목적·우선순위는 [`guide.md`](./guide.md)에 사용자가 직접 적습니다.

## 1. 정체성

**flick-server**는 넷플릭스·티빙류의 스트리밍(OTT) 서비스 백엔드다(2026-09-13 확정, 이전에는 채용정보 통합 서비스로 방향을 잡았었다 — 배경은 [`guide.md`](./guide.md) 참고). `flick`라는 저장소/패키지명은 이전 정체성(잡 어그리게이터)의 흔적이며 현재 서비스 정체성과는 무관하다.

> ⚠️ **레거시 코드베이스:** 이 저장소는 개인 운동 기록 서비스 `motive-server`를 복제한 초기 스캐폴딩이다. 운동 관련 도메인 패키지(`admin/exercise`·`fitness`·`workout`·`recommend`·`aichat`)는 2026-09-09 전부 제거했고, 그 뒤 시도했던 채용정보(잡 어그리게이터) 도메인(`jobposting`, 잡코리아 크롤러 포함)도 2026-09-13 코드+DB까지 전부 제거했다 — 스트리밍 도메인 기능은 아직 구현 전이며, 인증·3계층 구조·공통 응답 등 기술 골격만 재사용 가능한 상태로 남아있다.

| 항목          | 내용                                                           |
| ------------- | -------------------------------------------------------------- |
| 패키지 루트   | `kr.co.flick`                                                 |
| 그룹/버전     | `kr.co.flick` / `0.0.1-SNAPSHOT` (build.gradle)               |
| 실행 포트     | `9090` (local 프로파일)                                        |
| API 프리픽스  | `/api/v1` (WebConfig가 `@RestController` 전체에 자동 부여)     |
| 활성 프로파일 | `local` (기본), `dev` 존재. `secret` 프로파일을 항상 `include` |

## 2. 제공 기능 (컨트롤러 기준 실측)

- **인증** — 소셜 로그인(카카오/구글/깃허브) → JWT 발급, 액세스 토큰 재발급, 내 정보 조회
- **공통코드** — 공개 조회(2종), 관리자 CRUD(공통코드+상세코드)
- **메뉴** — 전체 메뉴 조회 (공개)
- **파일** — 에디터 이미지 업로드 (로컬 디스크 `C:/upload`)

## 3. 이것과 다른 저장소의 관계

- flick의 프론트엔드는 아직 정해지지 않았다. 현재 `CorsConfig`가 허용하는 오리진(`http://localhost:3000` 등)은 motive-server 시절 프론트엔드(`motive-ui`, Next.js) 개발 포트가 그대로 남아있는 것이며, flick 자체 프론트엔드가 정해지면 갱신이 필요하다.

## 4. 워크플로우 요약

```
소셜 로그인(OAuth2) → JWT 발급(Access 30분/Refresh 14일, Redis 저장)
```

flick 고유의 온보딩/도메인 워크플로우는 아직 설계 전이다.
